# Blogger / GitHub Pages 운영 실험

## 목적

실제로 검색 관심이 관측된 사건을 영어 기사로 제공하고, 같은 운영 방식에서 Blogger와 GitHub Pages의 검색 유입·수익·운영 품질을 비교한다. 목표는 매시간 고유 기사 한 편, 두 사이트 합계 하루 24개 발행 슬롯이며 사이트별 목표는 12편이다. 이는 운영 목표이며 매일 24편의 공개나 검색 유입을 보장하지 않는다. 플랫폼당 사이트가 하나이므로 플랫폼 일반의 인과적 우열을 증명하는 A/B 테스트로 해석하지 않는다.

독자용 제목·본문·설명은 영어로 작성한다. 미국(US)과 영국(GB)의 검색 수요와 유입을 분리해서 관측하고, 다른 국가의 유입은 보조 지표로 기록한다. 영어 사용 자체가 특정 국가의 유입이나 광고 수익을 보장하지는 않는다.

## 후보 범위

소비자 기술의 특정 분야에 고정하지 않고 다음과 같은 넓은 후보군에서 현재 검색 관심이 큰 사건을 찾는다. 초기에는 카테고리별 발행 비율이나 할당량을 두지 않는다. 실제 수요·검증 가능성·발행 후 실적을 기록해 후보 선택을 조정한다.

| 후보군 | 조사할 사건의 예 |
| --- | --- |
| 엔터테인먼트·스트리밍·크리에이터 행사 | 작품 공개, 새 회차, 시상식, 공식 행사와 일정 변경 |
| 스포츠 | 실제 진행되는 경기·라운드, 결과, 다음 일정과 공식 발표 |
| 계절성 소비자 출시·행사 | 시즌 상품, 한정 출시, 공식 판매·행사 일정 |
| 주요 게임·제품 | 실측 검색 수요가 선별 기준을 충족하는 출시·발표·변경 |

유명한 제품·브랜드라는 이유만으로 소재를 우선하지 않는다. 최근 사건의 존재와 검색 수요는 별도로 확인하고, 기사마다 실제로 답할 질문과 독자에게 제공할 정보를 명시한다.

## 후보 발견과 수요 검증

매시간 후보를 재확인하고, 출처·원고·중복 검수를 통과한 기사 한 편을 두 사이트 중 한 곳에 발행하는 운영을 목표로 한다. 후보 발견, 원고 생성, 검수, 공개 완료는 각각 다른 단계다. 슬롯을 채우기 위한 재작성이나 확인되지 않은 속보는 발행하지 않는다. 통과한 후보가 없으면 슬롯을 비우고 사유를 기록한다.

1. **수요 후보 발견:** Google Trending now에서 US와 GB를 각각 관측한다. 4시간 신규 추세 필터로 새 후보를 찾고, 24시간 창의 검색량 정렬로 관심 규모를 비교하며, 7일 창으로 지속·반복 신호를 확인한다. 필요할 때 최근 7–14일의 공식 사건 기록과 Explore 사용자 지정 기간을 보조 자료로 사용한다.
2. **초기 선별:** 24시간 창에서 US `50K+`, GB `10K+` 이상의 표시 구간을 우선 검토한다. 이는 초기 실험을 위한 선별 가정이며 Google의 권장 기준, 정확한 검색량, 예상 방문자 수 또는 수익 보장이 아니다. 더 작은 신흥 추세는 공식 사건·새 경기·새 회차 등이 실제로 확인되고 출처 본문에 날짜·시각 근거가 있을 때만 탐색 후보로 검토한다. 기준 변경은 적용일과 이유를 기록한다.
3. **사건과 시각 확인:** 주최자·리그·스트리밍 서비스·제조사 등의 공식 공지, 일정, 결과 기록에서 실제 사건과 날짜·시각·시간대를 확인한다. 자료를 수집한 시각, 문서의 수정일, 사건 발생일을 구분한다. 같은 출처의 실제 갱신 기록을 확인하고, 검색 결과에 새 날짜가 표시된 것만으로 새 사건이나 다음 라운드를 단정하지 않는다.
4. **별칭 통합과 기사 각도 결정:** 팀명·작품명·약칭·관련 검색어를 같은 사건으로 묶어 `story_id`를 부여한다. 해당 사건의 소유 플랫폼과 원문 URL을 확인한 뒤 독자가 알고 싶어 하는 질문, 현재 확인된 사실, 남아 있는 불확실성을 정리한다. 사건 전체의 관심을 개별 질문의 검색량으로 간주하지 않는다.
5. **출처·추가 가치 검수:** 사실 확인, 시간대·지역 조건 정리, 공식 정보의 비교·맥락 등 기사 고유의 가치를 확인한다. 다른 기사의 단순 재작성이나 확인하지 않은 직접 경험을 포함하지 않는다. AI 보조 원고는 제목·설명·본문·구조화 데이터까지 정확성과 출처를 검토한 뒤 공개 대상으로 지정한다.
6. **발행 또는 보류:** 수요 근거, 사건의 최신성, 출처, 추가 가치와 중복 검사를 통과한 후보만 배정한다. 수요 미확인·오래된 사건·불명확한 출처·동일 사건 반복·원고 품질 부족은 각각 보류 사유로 기록한다. 발행 직전에 사건 상태를 다시 확인한다.

### Trends 기록 변수와 해석

후보별로 관측 시각, 국가(US/GB), 검색어 또는 Topic, 검색 표현의 언어, 기간·사용자 지정 날짜, 신규 추세·상태 필터, 정렬 방식, 카테고리·검색 유형, 출처 URL을 기록한다. 가능하면 관련 검색어, 추세의 시작·활성/종료 상태, 제공되는 검색량 구간과 기준선 대비 증가율도 함께 남긴다. 사건 근거의 실제 날짜·시각과 `story_id`도 연결한다. 서로 다른 설정으로 얻은 지수나 순위를 그대로 비교하지 않는다.

- Explore의 0–100 지수는 선택한 시간·지역의 전체 검색량으로 정규화한 상대적 관심도다. 절대 검색량이나 월간 방문자 수로 환산하지 않는다. 국가별 같은 지수가 같은 검색량을 뜻하지 않으며, 0도 검색이 전혀 없다는 증거는 아니다.
- Trending now는 4시간·24시간·48시간·7일 창을 제공한다. 14일 비교는 Explore의 사용자 지정 기간을 사용한다. Trending now의 검색량 구간은 선택한 기간의 추세에 대한 값이며, 묶인 관련 검색어 전체일 수 있다. 이를 개별 질문의 월간 검색량으로 적지 않는다.
- 4시간 신규 추세 목록과 24시간 목록은 같은 표본 집합이 아니다. 두 창의 표시값을 나눠 시간당 증가율·가속도를 만들지 않는다. 같은 조건의 연속 관측을 확보한 경우에도 표시 구간의 변화를 정확한 검색량 증가율로 환산하지 않는다.
- 같은 사건의 별칭·관련 검색어 행은 겹칠 수 있으므로 검색량 구간을 합산하지 않는다. US와 GB의 관측도 별도로 유지한다. 24시간·7일 수치를 더하거나 하나의 월간 규모로 환산하지 않는다.
- 검색어는 입력한 언어·표현의 영향을 받으며, Topic은 여러 언어의 같은 개념을 묶을 수 있다. Topic의 상승만으로 영어의 특정 질문에 수요가 있다고 결론 내리지 않는다.
- Rising·Breakout은 증가율 신호다. 작은 기준값에서 급증한 검색어를 큰 시장으로 해석하지 않는다. 최근 사건의 존재, 관심도의 증가, 우리 글의 실제 검색 노출은 각각 따로 기록한다.
- Keyword Planner의 광고주 입찰가나 광고주 경쟁도를 게시자의 Page RPM 또는 검색 상위 노출 난이도로 대체하지 않는다.

## 배정과 운영

초기 연결 확인용 Chrome·Edge 알림 원고 각 1편은 운영 리허설로 사용한다. 검색 수요가 검증된 소재가 아니며 정식 영어 운영의 무작위 배정 표본에도 포함하지 않는다. 아래 규칙의 비교는 정식 운영 시작 이후 배정한 글을 대상으로 한다.

1. 매시간 한 개의 공통 발행 슬롯을 두고, 하루 합계 24개 슬롯을 두 사이트에 목표 12개씩 배정한다. 사이트마다 24편을 발행하는 계획이 아니다. 계획 시각과 실제 공개 시각을 구분해서 UTC로 기록한다.
2. 가능하면 두 시간 블록마다 국가·카테고리·긴급성·관측 수요가 비슷한 서로 다른 사건의 기사 두 편을 짝짓는다. 어느 기사를 어느 플랫폼에 보낼지와 어느 시간 슬롯에 공개할지를 발행 전에 무작위로 정하고 배정을 유지한다. 매칭이 어렵거나 급한 사건 때문에 규칙을 달리 적용하면 이유를 남기고 해당 표본을 구분한다.
3. 슬롯마다 검수를 통과한 고유 기사만 공개한다. 보류·실패로 빈 슬롯이 생길 수 있으며, 부족분을 중복 기사나 다음 실행의 일괄 공개로 채우지 않는다. 목표 24개 슬롯과 실제 공개 편수를 별도로 보고한다. 특정 글자 수나 게시량이 승인을 보장하지 않는다.
4. 같은 사건·질문을 두 사이트에 중복 배정하지 않는다. 같은 원문을 복제하거나 문장만 바꾼 글도 발행하지 않는다. 동일 사건의 새 정보는 소유 플랫폼의 원래 URL에서 갱신하고 변경일·이유를 기록한다. 같은 팀·작품이라도 실제 새 경기·회차가 공식 기록으로 확인되면 별도 사건으로 검토할 수 있다. 단순 순위 변화는 새 사건이 아니다.
5. 사건의 별칭, 원문 URL, 기사 ID와 발행 결과를 공통 기록으로 관리한다. 현재의 파일 ID·동일 본문 검사만으로 의미상 중복이 모두 검출된다고 가정하지 않는다. 중복 콘텐츠 자체가 자동 제재를 의미하지는 않지만 대표 URL 선택이 비교에 섞일 수 있다.
6. 발행 일정·출처 검증·광고 설정·외부 홍보 조건을 가능한 범위에서 맞춘다. 조건을 바꾸면 날짜와 이유를 남긴다.

### 14일 주기와 30일 검토

- 첫 14일에는 후보 발견, 검수, 배정과 발행을 진행하면서 색인·최초 노출·오류를 확인한다. 단기 사건이 끝나도 도움이 되는 기사와 빠르게 만료되는 기사를 따로 표시하고, 목표 슬롯과 실제 발행 이행률을 함께 본다.
- 다음 14일에는 같은 규칙으로 운영하고, 관측 기간을 채운 첫 주기의 글을 검토한다. 오래 쓰이는 설명은 사실을 재확인해 갱신하고, 종료된 이벤트는 종료 상태를 명시한다. 새로워 보이게 하려고 날짜만 바꾸지 않는다.
- 30일 검토는 중간 점검이다. 마지막에 발행한 글은 14일 관측을 채울 때까지 추적한다. 후보 선별 기준이나 발행 규칙을 바꾸면 다음 운영 주기로 구분하고, 변경 전후 표본을 그대로 합쳐 비교하지 않는다.

## 지표

- 주지표: 글당 최초 14개 완결 보고일의 Google 검색 클릭 수. 발행 다음 날부터 14일을 고정해서 관측하며, 그 기간을 채운 글만 비교한다. 색인되지 않아 클릭이 0인 글도 전체 발행 성과에 포함한다.
- 보조 검색 지표: 노출수, CTR, 최초 검색 노출일, 색인·대표 URL 상태, 쿼리·국가·기기·카테고리·발행 시간대별 변화. US와 GB를 분리한다. 전체 평균 게재순위만으로 판정하지 않는다.
- 집계 규칙: 발행 시각은 UTC로 보관하고 Search Console의 일별 보고일은 태평양 시간 기준으로 맞춘다. 최신 잠정 데이터는 최종 판정에서 제외한다. 익명화·데이터 제한 때문에 쿼리 목록이 모든 검색을 포함하지 않는다는 점을 기록한다.
- 사업 지표: 30일 누적 추정 광고 수익, 확정 수익, 실제 입금, API·도구 비용, 운영 시간. 서로 다른 항목을 혼합하지 않는다.
- 수익 효율: 양쪽 모두 광고를 게재한 공통 기간의 페이지 RPM. 국가·기기·유입 경로 구성이 다르면 이를 함께 본다.
- 운영 이행: 계획 슬롯 수, 실제 공개 편수, 빈 슬롯과 사유, 예정 시각 대비 공개 지연, 실패·결과 불명·복구 횟수. 공개 성공률은 실제 공개 완료 슬롯 수를 계획 슬롯 수로 나눠 계산한다.
- 운영 품질: 고유 사건 수, 중복으로 보류한 후보 수, 검수 글/사실 오류 글 수, 수정에 사용한 시간, 글당 조사·생성 비용과 운영 시간.

## 승인 시차와 판정

AdSense 신청일, 승인일, 실제 광고 게재 시작일을 따로 기록한다. 승인 전 수익 0원은 실제 사업 성과에 포함하지만 RPM은 미측정이다. 검색 유입과 광고 심사 상태는 별개로 관측한다.

관측 기간을 채운 글 쌍이 부족하거나, 노출이 너무 적어 비교가 한두 번의 클릭에 좌우되거나, 한 편의 급등이 전체 차이를 만드는 경우에는 판정을 보류한다. 이 실험에는 통계적 우위를 보장하는 최소 표본 수가 정해져 있지 않다. 30일에 반드시 플랫폼 승자를 정하지 않으며, 한두 글의 성과를 플랫폼 전체의 우위로 확대하지 않는다.

색인·접근·대표 URL 문제가 있으면 이를 먼저 해결하고 기록한다. 정상적으로 노출되는 글에서 반복적으로 확인되는 질문·국가·주제군을 다음 주기의 후보 선택에 사용한다. 사실 오류·중복 질문·추가 가치 부족은 해당 글의 발행을 중단하는 사유이며, 수요 데이터 부족은 수요 검증을 보류하는 사유다.

### 수익 산식

다음 산식의 수익과 비용은 같은 기간·통화로 맞춘다. Page RPM의 페이지 조회 수는 AdSense 보고서와 같은 범위의 분모를 사용하며, 광고가 없는 페이지까지 포함한 다른 도구의 전체 조회 수와 섞지 않는다.

```text
실측 Page RPM = 추정 광고 수익 ÷ AdSense 페이지 조회 수 × 1,000
시나리오 광고 수익 = 시나리오 페이지 조회 수 ÷ 1,000 × 가정 Page RPM
운영 수지 = 광고 수익 − 운영 비용
목표 달성에 필요한 페이지 조회 수 = (목표 운영 수지 + 운영 비용) × 1,000 ÷ 가정 Page RPM
```

가정 Page RPM은 계산을 위한 입력값이며 시장 평균·예상 실적·수익 보장이 아니다. 광고 게재 후 충분한 관측이 쌓이면 실제 국가·기기·유입 구성에 맞는 실측값으로 교체한다. 단기 급등을 유지 가능한 월간 수익으로 간주하지 않는다. 월 환산 수익, 기간 누적 수익, 확정 수익, 실제 입금은 별도로 표시한다.

## 현재 자동화 범위

2026년 10월 17일 기준, 매시간 조사부터 공개까지 이어지는 발행 연결은 완료되지 않았다. 이 문서의 시간당 발행 목표를 실행 중인 기능으로 표시하지 않는다.

| 단계 | 현재 상태와 연결할 작업 |
| --- | --- |
| GitHub Pages 재빌드 | `17 0,9 * * *` 일정으로 UTC 00:17·09:17, 한국시간 09:17·18:17에 이미 준비된 원고를 재빌드한다. 매시간 원고를 만드는 일정은 아니다. |
| 후보 조사·영어 원고 생성 | Trends·검색의 자동 수집, 사건 조사, AI 원고 생성과 검수 연결이 아직 없다. |
| 시간 슬롯·사건 대기열 | 두 사이트 공통 슬롯 관리, 의미상 중복 검사, 지속 상태와 공개 결과 확인이 추가로 필요하다. 현재 빌더는 시간이 지난 모든 `ready` 원고를 출력하므로 밀린 여러 신규 글이 한꺼번에 공개될 수 있다. |
| Blogger 발행 | API 발행기 코드는 있으나 OAuth와 정기 실행이 연결되지 않았다. 비공개 저널 보존과 단일 발행 실행자를 준비해야 한다. 기존 본문 자동 갱신도 현재 발행기에는 없다. |
| ChatGPT 예약·Blogger 플러그인 | QuickIris용 예약 자동화는 생성되지 않았다. 확인한 플러그인 검색에서는 사용 가능한 Blogger 플러그인을 찾지 못했으며 연결이 완료된 것으로 간주하지 않는다. |
| 검색·수익 측정 | Search Console·광고 수익 데이터의 자동 수집이 아직 연결되지 않았다. |

스케줄러는 작업을 시작시키는 장치다. 자료 접근, 원고 생성, 검수, 대기열, 각 사이트의 인증·공개, 실패 복구가 실제로 연결되어야 매시간 전체 발행을 실행할 수 있다. 준비되지 않은 단계가 남은 상태에서 재빌드 cron만 매시간으로 바꾸어 전체 자동 발행이 켜졌다고 표시하지 않는다. 예약 지연·누락에 대비해 계획 시각과 실제 완료 상태를 보존한다.

## 기록 파일

실제 계정·수익·성능 데이터는 공개 저장소에 넣지 않는다. `data/private/`는 Git에서 제외한다. 후보 근거·배정·관측값은 비공개 기록으로 관리하고, 공개 문서에는 실험 설계·지표 산식·코드만 저장한다. 개인 연락처, 사용자 대화, 개인 재정 정보는 포함하지 않는다.
