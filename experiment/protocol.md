# Blogger / GitHub Pages 운영 실험

## 목적

영어로 작성한 소비자용 문제 해결 콘텐츠가 어떤 검색 질문에서 방문자를 얻는지 확인하고, 같은 운영 방식에서 Blogger와 GitHub Pages의 성과를 비교한다. 플랫폼당 사이트가 하나이므로 플랫폼 일반의 인과적 우열을 증명하는 A/B 테스트로 해석하지 않는다.

독자용 제목·본문·설명은 영어로 작성한다. 미국(US)과 영국(GB)의 검색 수요와 유입을 분리해서 관측하고, 다른 국가의 유입은 보조 지표로 기록한다. 영어 사용 자체가 특정 국가의 유입이나 광고 수익을 보장하지는 않는다.

## 주제 가설

소비자 기술 제품·서비스에서 최근 7–14일 동안 발생한 변화 중 실제 사용자가 해결할 질문을 찾는다. 아래 비중은 첫 운영 주기의 시험 가설이며 고정 의무가 아니다. 관측한 수요와 발행 후 실적에 따라 조정하고, 자료로 확인하지 않은 주제 순위를 고정하지 않는다.

| 주제군 | 배정 목표 | 다룰 질문 |
| --- | --- | --- |
| 앱·OS 변경 | 40% | 소비자 앱·브라우저·개인용 Windows 등의 업데이트나 정책 변경 이후 사용 방법, 설정 변화, 호환성·작동 조건 |
| 게임 구독 서비스 변경 | 30% | 구독 요금제·포함 게임·제공 기간·플랫폼·지역 조건의 최근 변경 |
| AI 앱·신제품의 이용 조건 | 30% | 최근 공개된 앱·기능·제품을 사용할 수 있는 국가, 계정·요금제, 기기·플랫폼, 순차 배포 조건 |

글마다 주제군 하나를 지정한다. 같은 주제군의 질문 쌍을 배정하는 방식으로 두 사이트의 구성을 맞춘다. 예를 들어 10쌍을 확보했다면 4쌍·3쌍·3쌍으로 구성할 수 있지만, 비중을 맞추기 위해 검수를 통과하지 못한 소재를 발행하지 않는다. 계정별 순차 배포를 모든 사용자의 이용 가능 상태로 단정하지 않는다.

## 후보 발견과 수요 검증

운영 계획은 하루 두 번 후보를 발견·갱신하고, 검수를 통과한 글만 사이트당 하루 최대 한 편 발행하는 것이다. 후보 발견 횟수와 발행 횟수는 별개다. 최신 뉴스의 요약에서 그치지 않고, 사용자가 지금 실행할 수 있는 설명·조건 확인·문제 해결 절차를 제공한다.

1. **최근 사건 확인:** 공식 릴리스 노트·공지·도움말에서 실제 변화와 발생일을 확인한다. 문서의 수정일과 기능의 공개일을 구분한다. 최근에 수정된 문서라는 이유만으로 새 사건으로 분류하지 않는다.
2. **질문 구체화:** 사건을 사용자의 질문으로 바꾸고 대상 국가·제품·버전·계정 조건을 적는다. 사건의 인기와 그 질문의 검색 수요를 같은 것으로 취급하지 않는다.
3. **검색 수요 확인:** US와 GB를 각각 설정한 Trends, 관련 검색어, 확보된 Search Console 데이터를 확인한다. 관측값이 없으면 미확인으로 남긴다. 실제로 확인하지 않은 검색량이나 추세 수치를 기입하지 않는다.
4. **추가 가치 확인:** 공식 문서에 흩어진 조건의 비교, 직접 확인한 절차, 재현 가능한 예시 등 글이 제공할 추가 가치를 명시한다. 확인하지 않은 직접 사용 경험을 만들어 내지 않는다.
5. **발행 또는 보류:** 사건·답변의 출처가 확인되고, 수요 근거 또는 제한된 탐색 실험의 이유가 있으며, 독립적인 답변을 제공할 수 있는 후보만 배정한다. 수요 미확인 탐색 글은 검증된 수요의 글과 구분해서 기록한다. 사실을 확인할 수 없거나 기존 글과 같은 질문이면 보류한다.

### Trends 기록 변수와 해석

후보별로 관측 시각, 국가(US/GB), 검색어 또는 Topic, 검색 표현의 언어, 기간·사용자 지정 날짜, 카테고리·검색 유형, 출처 URL을 기록한다. 가능하면 관련 검색어, 추세의 활성/종료 상태, 제공되는 검색량 구간과 기준선 대비 증가율도 함께 남긴다. 서로 다른 설정으로 얻은 지수를 그대로 비교하지 않는다.

- Explore의 0–100 지수는 선택한 시간·지역의 전체 검색량으로 정규화한 상대적 관심도다. 절대 검색량이나 월간 방문자 수로 환산하지 않는다. 국가별 같은 지수가 같은 검색량을 뜻하지 않으며, 0도 검색이 전혀 없다는 증거는 아니다.
- Trending now는 4시간·24시간·48시간·7일 창을 제공한다. 14일 비교는 Explore의 사용자 지정 기간을 사용한다. Trending now의 검색량 구간은 선택한 기간의 추세에 대한 값이며, 묶인 관련 검색어 전체일 수 있다. 이를 개별 질문의 월간 검색량으로 적지 않는다.
- 검색어는 입력한 언어·표현의 영향을 받으며, Topic은 여러 언어의 같은 개념을 묶을 수 있다. Topic의 상승만으로 영어의 특정 질문에 수요가 있다고 결론 내리지 않는다.
- Rising·Breakout은 증가율 신호다. 작은 기준값에서 급증한 검색어를 큰 시장으로 해석하지 않는다. 최근 사건의 존재, 관심도의 증가, 우리 글의 실제 검색 노출은 각각 따로 기록한다.
- Keyword Planner의 광고주 입찰가나 광고주 경쟁도를 게시자의 Page RPM 또는 검색 상위 노출 난이도로 대체하지 않는다.

## 배정과 운영

초기 연결 확인용 Chrome·Edge 알림 원고 각 1편은 운영 리허설로 사용한다. 검색 수요가 검증된 소재가 아니며 정식 영어 운영의 무작위 배정 표본에도 포함하지 않는다. 아래 규칙의 비교는 정식 운영 시작 이후 배정한 글을 대상으로 한다.

1. 같은 언어·분야·대상 국가·검색 의도·시의성·예상 난이도의 서로 다른 질문을 한 쌍으로 만든다.
2. 쌍 안에서 어느 질문을 어느 플랫폼에 보낼지 발행 전에 무작위로 정하고 배정을 유지한다.
3. 30일 동안 사이트당 하루 최대 한 편을 발행한다. 데이터·원고 검증을 통과한 글만 발행하며, 발행하지 않은 날도 기록한다. 특정 글자 수나 게시량이 승인을 보장하지 않는다.
4. 같은 질문을 두 사이트에 중복 배정하지 않는다. 같은 원문을 복제하거나 문장만 바꾼 글도 발행하지 않는다. 기존 질문의 새 정보는 원래 글을 갱신하고 변경일·이유를 기록한다. 중복 콘텐츠 자체가 자동 제재를 의미하지는 않지만 대표 URL 선택이 비교에 섞일 수 있다.
5. 발행 일정·출처 검증·광고 설정·외부 홍보 조건을 가능한 범위에서 맞춘다. 조건을 바꾸면 날짜와 이유를 남긴다.

### 14일 주기와 30일 검토

- 첫 14일에는 후보 발견, 검수, 배정과 발행을 진행하면서 색인·최초 노출·오류를 확인한다. 단기 사건이 끝나도 도움이 되는 질문과 빠르게 만료되는 질문을 따로 표시한다.
- 다음 14일에는 같은 규칙으로 운영하고, 관측 기간을 채운 첫 주기의 글을 검토한다. 오래 쓰이는 설명은 사실을 재확인해 갱신하고, 종료된 이벤트는 종료 상태를 명시한다. 새로워 보이게 하려고 날짜만 바꾸지 않는다.
- 30일 검토는 중간 점검이다. 마지막에 발행한 글은 14일 관측을 채울 때까지 추적한다. 주제 비중이나 발행 규칙을 바꾸면 다음 운영 주기로 구분하고, 변경 전후 표본을 그대로 합쳐 비교하지 않는다.

## 지표

- 주지표: 글당 최초 14개 완결 보고일의 Google 검색 클릭 수. 발행 다음 날부터 14일을 고정해서 관측하며, 그 기간을 채운 글만 비교한다. 색인되지 않아 클릭이 0인 글도 전체 발행 성과에 포함한다.
- 보조 검색 지표: 노출수, CTR, 최초 검색 노출일, 색인·대표 URL 상태, 쿼리·국가·기기별 변화. US와 GB를 분리한다. 전체 평균 게재순위만으로 판정하지 않는다.
- 집계 규칙: 발행 시각은 UTC로 보관하고 Search Console의 일별 보고일은 태평양 시간 기준으로 맞춘다. 최신 잠정 데이터는 최종 판정에서 제외한다. 익명화·데이터 제한 때문에 쿼리 목록이 모든 검색을 포함하지 않는다는 점을 기록한다.
- 사업 지표: 30일 누적 추정 광고 수익, 확정 수익, 실제 입금, API·도구 비용, 운영 시간. 서로 다른 항목을 혼합하지 않는다.
- 수익 효율: 양쪽 모두 광고를 게재한 공통 기간의 페이지 RPM. 국가·기기·유입 경로 구성이 다르면 이를 함께 본다.
- 운영 품질: 발행 시도/실패 횟수, 검수 글/사실 오류 글 수, 수정에 사용한 시간.

## 승인 시차와 판정

AdSense 신청일, 승인일, 실제 광고 게재 시작일을 따로 기록한다. 승인 전 수익 0원은 실제 사업 성과에 포함하지만 RPM은 미측정이다. 검색 유입과 광고 심사 상태는 별개로 관측한다.

관측 기간을 채운 글 쌍이 부족하거나, 노출이 너무 적어 비교가 한두 번의 클릭에 좌우되거나, 한 편의 급등이 전체 차이를 만드는 경우에는 판정을 보류한다. 이 실험에는 통계적 우위를 보장하는 최소 표본 수가 정해져 있지 않다. 30일에 반드시 플랫폼 승자를 정하지 않으며, 한두 글의 성과를 플랫폼 전체의 우위로 확대하지 않는다.

색인·접근·대표 URL 문제가 있으면 이를 먼저 해결하고 기록한다. 정상적으로 노출되는 글에서 반복적으로 확인되는 질문·국가·주제군을 다음 주기의 후보 선택에 사용한다. 사실 오류·중복 질문·추가 가치 부족은 해당 글의 발행을 중단하는 사유이며, 수요 데이터 부족은 수요 검증을 보류하는 사유다.

### 수익 산식

다음 산식의 수익과 비용은 같은 기간·통화로 맞춘다. Page RPM의 페이지 조회 수는 AdSense 보고서와 같은 범위의 분모를 사용하며, 광고가 없는 페이지까지 포함한 다른 도구의 전체 조회 수와 섞지 않는다.

```text
실측 Page RPM = 추정 광고 수익 ÷ AdSense 페이지 조회 수 × 1,000
시나리오 광고 수익 = 시나리오 페이지 조회 수 ÷ 1,000 × 가정 Page RPM
운영 수지 = 광고 수익 − 운영 비용
목표 달성에 필요한 페이지 조회 수 = (목표 운영 수지 + 운영 비용) × 1,000 ÷ 가정 Page RPM
```

가정 Page RPM은 계산을 위한 입력값이며 시장 평균·예상 실적·수익 보장이 아니다. 광고 게재 후 충분한 관측이 쌓이면 실제 국가·기기·유입 구성에 맞는 실측값으로 교체한다. 단기 급등을 유지 가능한 월간 수익으로 간주하지 않는다. 월 환산 수익, 기간 누적 수익, 확정 수익, 실제 입금은 별도로 표시한다.

## 현재 자동화 범위

정적 사이트 빌드와 예약 시각 처리는 이미 준비된 원고를 대상으로 한다. 자동 주제 조사, Trends·Search Console 수요 데이터 수집, AI 원고 생성은 아직 연결되어 있지 않다. 이 문서의 하루 두 번 후보 발견은 운영 계획이며 실행 중인 자동 조사 작업을 뜻하지 않는다. 조사·검수·발행이 실제로 연결되기 전에는 전체 운영이 자동화되었다고 표시하지 않는다.

## 기록 파일

실제 계정·수익·성능 데이터는 공개 저장소에 넣지 않는다. `data/private/`는 Git에서 제외한다. 후보 근거·배정·관측값은 비공개 기록으로 관리하고, 공개 문서에는 실험 설계·지표 산식·코드만 저장한다. 개인 연락처, 사용자 대화, 개인 재정 정보는 포함하지 않는다.
