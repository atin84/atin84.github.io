# Blogger / GitHub Pages 운영 실험

## 목적

초기에는 스포츠 팬·관람객을 대상으로, 검색 관심과 공식 근거가 확인된 경기 정보를 제공한다. Blogger와 GitHub Pages를 함께 운영하며 같은 조건에서 검색 유입·수익·운영 품질을 비교한다. 발행은 경기 전 공지·일정 확정과 경기 후 공식 결과 등 실제 변화에 맞춘다. 시간당·일별 고정 발행량과 플랫폼별 편수 할당량을 두지 않는다. 플랫폼당 사이트가 하나이므로 플랫폼 일반의 인과적 우열을 증명하는 A/B 테스트로 해석하지 않는다.

2026년 10월 17일 확정한 첫 취재 범위는 NBA와 잉글랜드 프리미어리그(EPL)다. 두 리그를 함께 시작하고, 선정한 각 기사에 영어·한국어를 포함한 8개 언어 전체를 적용한 뒤 리그·언어별 데이터를 분석한다. 영어는 작성 기준 언어이며 공개 언어를 영어 또는 일부 언어로 제한하지 않는다. 국가와 언어는 별도 변수로 기록하고, 취재 리그의 국가를 실제 독자의 국가로 간주하지 않는다.

## 확정 운영 방향과 후보 범위

스포츠 팬·관람객이 경기를 따라가고 관람을 준비하는 데 필요한 질문을 우선한다. 리그·팀의 이름만으로 우선순위를 정하지 않고, 관측된 수요·사건의 시의성·공식 출처·기사의 추가 가치를 함께 확인한다.

팬과 처음 보는 독자가 경기의 재미를 이해하도록 돕는 것을 편집의 중심으로 둔다. 첫 운영에서는 NBA 농구와 EPL 축구의 데이터·근거·검수 체계를 각각 준비한다. MLB·NFL 등 다른 종목·리그는 첫 실험 범위에 자동 추가하지 않으며, 이후 관측을 근거로 확대 여부를 정한다. 경기 전의 관전 질문과 경기 후의 확인된 답을 연결하며, 쉬운 설명과 팬을 위한 깊은 맥락은 한 언어의 같은 페이지에서 제공한다. 구체적인 기사 형식은 [스포츠 편집 기준](editorial-guidelines.md)에 따른다.

| 상황 | 독자에게 제공할 정보 |
| --- | --- |
| 경기 전 공지·일정 확정 | 대진, 경기 시각과 시간대, 장소, 해당 국가에서 공식 확인된 관람·중계 정보 |
| 경기 후 공식 결과 | 확정된 결과, 경기의 의미, 다음 경기·라운드의 확인된 일정 |
| 변경·정정 | 연기·취소·장소·시각 변경, 공식 결과 정정과 후속 발표 |

사전 안내에는 경기의 중요성, 공식 확인된 주요 선수 관련 소식과 현지 관람 조건을 담고, 결과 기사에는 출처가 확인된 핵심 장면·타임라인과 순위·다음 라운드에 미친 영향을 담는다. 확인하지 않은 장면·선수 발언·인과관계를 AI가 채우지 않도록 한다. 영상 하이라이트는 공식 제공 영상의 링크를 우선한다.

정보량이 작은 경기는 기본적으로 하나의 경기 페이지에서 전후 정보를 갱신할 수 있다. 관심이 큰 경기에서는 사전 안내와 결과 분석이 각각 독립적인 정보를 제공할 때 프리뷰와 리캡을 나눌 수 있다. 모든 경기에 단일 페이지 또는 두 편을 의무적으로 적용하지 않는다. 경기 시계나 예상 종료 시각만으로 공식 결과가 확정됐다고 판단하지 않는다.

## 확정 언어와 전체 번역 발행

운영 언어는 영어(`en`), 한국어(`ko`), 스페인어(`es`), 일본어(`ja`), 브라질 포르투갈어(`pt-BR`), 프랑스어(`fr`), 독일어(`de`), 힌디어(`hi`)의 총 8개다. 이전의 추가 언어 후보·3개 기본 언어·5개 선별 번역 제안은 이 기준으로 대체한다. **두 리그 모두 선정한 모든 기사에 8개 언어 전체를 적용한다.**

경기 선정은 리그 단위로 수행하고, 해당 기사에 사용할 공통 사실·출처와 영어 기준 원고를 검수한 다음 7개 언어 번역을 준비한다. 번역은 다른 번역본을 차례로 재번역하지 않고 검증된 기준 정보에서 작성한다. 지역의 언어 사용 인구나 예상 광고 단가만으로 언어를 미리 제외하지 않는다. 언어별 수요가 미측정이어도 선정된 기사의 번역 대상에는 포함한다.

8개 언어판의 준비·검수 상태를 확인한 뒤 같은 발행 묶음으로 가까운 시각에 공개한다. 언어별 준비·검수·실제 공개 시각과 원문 버전, 발행 지연을 기록한다. 외부 요청 실패나 불확실한 결과는 복구 대상으로 유지한다. 일부 언어가 누락된 묶음은 부분 완료로 기록하며, 누락을 수요 0이나 의도적 언어 제외로 처리하지 않는다. 핵심 원문 오류·미확정 결과가 있으면 공통 원고를 고치고 모든 해당 언어판의 검수·갱신 상태를 갱신한다.

8개 언어 공개가 필수라는 기준이 모든 경기를 발행하거나 불확실한 정보를 공개하라는 뜻은 아니다. 처리량 조정이 필요하면 첫 실험에서는 선정 경기·기사 수를 조정하며, 공개 언어를 임의로 줄이지 않는다. 언어 구성 변경은 데이터 검토 후 별도 운영 결정으로 기록한다.

언어별 고유 URL과 번역 그룹, 상호 언어 전환 링크 및 `hreflang`을 구현한다. 실제 공개된 번역본만 연결하고 언어별 대표 URL을 유지한다. 제목·본문·메뉴·그림의 레이블을 해당 언어로 제공하며 8개 언어 본문을 한 페이지에 쌓지 않는다. 중계·관람 정보는 언어와 별개로 실제 이용 국가를 표시한다. 현재 생성기는 전역 영어 설정을 사용하며 이 다국어 기능은 아직 구현되지 않았다.

## 후보 발견과 수요 검증

NBA와 EPL의 경기 일정·공식 발표·결과 변화에 맞춰 후보를 확인하고, 필요한 신규 기사 또는 기존 기사 갱신을 처리한다. 조사 실행 주기와 신규 기사 수는 별개다. 후보 발견, 원고 생성, 검수, 공개 완료를 각각 기록하며, 검수를 통과한 후보가 없으면 발행하지 않고 사유를 남긴다.

예정 경기는 공식 일정과 팀·대회·비슷한 경기의 관측 수요를 이용해 검색 급등 전에 사전 후보로 준비한다. 비교 경기의 수요를 이번 경기의 확정 검색량으로 표시하지 않는다. Trending now에 아직 등장하지 않았다는 이유만으로 예정 경기의 수요를 0으로 처리하지 않으며, 게시만 하면 경기 시작 전에 색인된다고 가정하지 않는다.

1. **수요 후보 발견:** Google Trending now에서 조사 대상 국가를 각각 설정하고 스포츠 관련 추세를 확인한다. 4시간 신규 추세 필터로 새 후보를 찾고, 24시간 창의 검색량 정렬로 관심 규모를 비교하며, 7일 창으로 지속·반복 신호를 확인한다. 필요할 때 최근 7–14일의 공식 경기 기록과 Explore 사용자 지정 기간을 보조 자료로 사용한다. 관측하지 않은 국가·언어의 값은 미측정으로 남긴다.
2. **선별 기준과 가정:** 국가·리그·기사 의도에 맞는 관측 수요를 비교한다. 기존 US 24시간 `50K+`, GB 24시간 `10K+` 우선 검토 기준은 초기 탐색 가정으로만 참고하며 다른 국가에 그대로 적용하지 않는다. 표시 구간은 Google 권장 기준, 정확한 검색량, 예상 방문자 수 또는 수익 보장이 아니다. 더 작은 신흥 추세는 실제 경기·새 라운드 등 공식 사건과 출처 본문의 날짜·시각이 확인될 때 탐색 후보로 검토한다. 기준 변경은 적용일과 이유를 기록한다.
3. **경기와 시각 확인:** 주최자·리그·구단·공식 중계사의 공지, 일정, 결과 기록에서 실제 경기와 날짜·시각·시간대를 확인한다. 자료를 수집한 시각, 문서의 수정일, 사건 발생일을 구분한다. 검색 결과에 새 날짜가 표시된 것만으로 새 경기나 다음 라운드를 단정하지 않는다. 중계·관람 가능 지역도 공식 출처에서 확인한다.
4. **별칭 통합과 기사 각도 결정:** 팀명·약칭·관련 검색어를 경기 단위로 묶는다. 해당 경기의 소유 플랫폼과 기존 기사 URL을 확인한 뒤 독자가 알고 싶어 하는 질문, 현재 확인된 사실, 남아 있는 불확실성을 정리한다. 팀 또는 대회 전체의 관심을 개별 경기·질문의 검색량으로 간주하지 않는다.
5. **출처·추가 가치 검수:** 사실 확인, 시간대·지역 조건 정리, 공식 정보의 비교·맥락 등 기사 고유의 가치를 확인한다. 다른 기사의 단순 재작성이나 확인하지 않은 직접 경험을 포함하지 않는다. AI 보조 원고는 제목·설명·본문·구조화 데이터까지 정확성과 출처를 검토한 뒤 공개 대상으로 지정한다.
6. **발행·갱신 또는 보류:** 수요 근거, 경기 정보의 최신성, 출처, 추가 가치와 중복 검사를 통과한 후보만 처리한다. 기존 기사에 새 정보를 반영할 수 있으면 같은 URL을 갱신한다. 수요 미확인·오래된 정보·불명확한 출처·동일 기사 반복·원고 품질 부족은 각각 보류 사유로 기록한다. 공개 직전에 경기 상태를 다시 확인한다.

### Trends 기록 변수와 해석

후보별로 관측 시각, 조사 국가, 검색어 또는 Topic, 검색 표현의 언어, 기간·사용자 지정 날짜, 신규 추세·상태 필터, 정렬 방식, 카테고리·검색 유형, 출처 URL을 기록한다. 가능하면 관련 검색어, 추세의 시작·활성/종료 상태, 제공되는 검색량 구간과 기준선 대비 증가율도 함께 남긴다. 공식 경기 근거의 실제 날짜·시각과 경기 식별자를 연결한다. 서로 다른 설정으로 얻은 지수나 순위를 그대로 비교하지 않는다.

- Explore의 0–100 지수는 선택한 시간·지역의 전체 검색량으로 정규화한 상대적 관심도다. 절대 검색량이나 월간 방문자 수로 환산하지 않는다. 국가별 같은 지수가 같은 검색량을 뜻하지 않으며, 0도 검색이 전혀 없다는 증거는 아니다.
- Trending now는 4시간·24시간·48시간·7일 창을 제공한다. 14일 비교는 Explore의 사용자 지정 기간을 사용한다. Trending now의 검색량 구간은 선택한 기간의 추세에 대한 값이며, 묶인 관련 검색어 전체일 수 있다. 이를 개별 질문의 월간 검색량으로 적지 않는다.
- 4시간 신규 추세 목록과 24시간 목록은 같은 표본 집합이 아니다. 두 창의 표시값을 나눠 시간당 증가율·가속도를 만들지 않는다. 같은 조건의 연속 관측을 확보한 경우에도 표시 구간의 변화를 정확한 검색량 증가율로 환산하지 않는다.
- 같은 경기의 별칭·관련 검색어 행은 겹칠 수 있으므로 검색량 구간을 합산하지 않는다. 국가별 관측은 별도로 유지한다. 24시간·7일 수치를 더하거나 하나의 월간 규모로 환산하지 않는다.
- 검색어는 입력한 언어·표현의 영향을 받으며, Topic은 여러 언어의 같은 개념을 묶을 수 있다. Topic의 상승만으로 영어의 특정 질문에 수요가 있다고 결론 내리지 않는다.
- Rising·Breakout은 증가율 신호다. 작은 기준값에서 급증한 검색어를 큰 시장으로 해석하지 않는다. 최근 사건의 존재, 관심도의 증가, 우리 글의 실제 검색 노출은 각각 따로 기록한다.
- Keyword Planner의 광고주 입찰가나 광고주 경쟁도를 게시자의 Page RPM 또는 검색 상위 노출 난이도로 대체하지 않는다.

## 배정과 운영

초기 연결 확인용 Chrome·Edge 알림 원고 각 1편은 운영 리허설로 사용한다. 검색 수요가 검증된 소재가 아니며 정식 NBA·EPL·8개 언어 운영의 배정 표본이나 번역 의무 대상에 포함하지 않는다. 아래 규칙의 비교는 정식 운영 시작 이후 배정한 글을 대상으로 한다.

1. 발행량은 경기와 확인된 정보에 따라 달라진다. 경기 전 안내·일정 확정과 경기 후 공식 결과에 맞춰 필요한 기사나 갱신을 처리하며, 시간당·일별 편수 할당량을 적용하지 않는다. 공식 변화 확인 시각과 실제 공개·갱신 시각을 구분해서 UTC로 기록한다.
2. 같은 리그 안에서 관측 수요·경기 중요도·예정 시각이 비슷한 서로 다른 경기를 가능하면 짝짓는다. 각 경기의 플랫폼을 발행 전에 무작위로 배정하고 유지한다. 매칭이 어려우면 이유를 남긴다. 같은 경기의 선정된 기사·8개 언어판·후속 갱신은 모두 소유 플랫폼에서 관리한다. NBA를 GitHub에, EPL을 Blogger에 고정하거나 언어를 플랫폼별로 나누지 않는다. 양쪽에 두 리그와 같은 8개 언어 구성이 쌓이도록 리그별 배정 현황을 확인한다.
3. 검수를 통과한 신규 원문·7개 번역본·기존 기사 갱신을 처리한다. 같은 번역 그룹의 8개 언어판으로 언어 반응을 비교하고, 플랫폼 비교는 같은 리그·언어·기사 의도의 매칭 경기끼리 수행한다. 언어판을 독립된 경기 표본처럼 세지 않는다. 특정 글자 수나 게시량이 승인을 보장하지 않는다.
4. 같은 경기·같은 기사 의도·같은 언어의 글을 두 사이트에 중복 배정하지 않는다. 같은 원문을 복제하거나 문장만 바꾼 글도 발행하지 않는다. 동일 기사의 새 정보는 소유 플랫폼의 원래 URL에서 갱신하고 변경일·이유를 기록한다. 실제 다른 경기·라운드가 공식 기록으로 확인되면 별도 경기로 검토한다.
5. 단일 경기 페이지는 전후 정보를 갱신할 수 있고, 프리뷰·리캡은 독립적인 정보와 독자 질문이 있을 때 각각 발행할 수 있다. 번역은 같은 기사 의도의 다른 언어 버전으로 구분한다. 단순 검색 순위 변화나 번역 수 증가는 새 경기 발생이 아니다.
6. 경기 별칭, 원문·번역 URL, 기사 ID와 공개·갱신 결과를 공통 기록으로 관리한다. 현재 파일 ID·동일 본문 검사만으로 의미상 중복이 모두 검출된다고 가정하지 않는다. 중복 콘텐츠 자체가 자동 제재를 의미하지는 않지만 대표 URL 선택이 비교에 섞일 수 있다.
7. 출처 검증·광고 설정·외부 홍보 조건을 가능한 범위에서 맞춘다. 조건을 바꾸면 날짜와 이유를 남긴다.

### 구현할 경기·기사·번역 식별 규칙

아래는 운영 기록과 후속 코드에 반영할 설계이며 현재 원고 스키마에 구현 완료된 필드가 아니다.

```text
league_id = nba 또는 epl
match_id = 리그·시즌과 공식 경기 ID를 포함한 안정적인 식별자
기사 중복 키 = match_id + article_kind + language
번역 그룹 = match_id + article_kind
필수 언어 = en, ko, es, ja, pt-BR, fr, de, hi
소유 플랫폼 = match_id 단위로 유지
발행 묶음 완료 = 해당 기사 의도의 필수 8개 언어 URL 모두 공개 확인
```

`article_kind`는 단일 경기 페이지(`match`), 독립 사전 안내(`preview`), 독립 결과 기사(`recap`)처럼 실제 기사 의도를 구분한다. 같은 의도의 언어별 번역본은 중복 키가 다르지만 같은 번역 그룹에 속한다. 원문이 바뀌면 번역본에도 갱신 필요 상태를 남겨 언어별로 결과·일정이 어긋나지 않게 한다. 최초 공개일과 실제 수정일은 따로 관리한다.

### 리그·언어 비교와 표본 구성

기본 분석 조합은 **2개 리그 × 8개 언어 = 16개**다. 여기에 플랫폼을 나누면 32개 관측 조합이지만 32개의 독립 사이트나 경기 표본을 뜻하지 않는다. 기사 의도와 실제 독자 국가는 추가 분석 차원으로 기록한다.

매 보고서에는 리그·언어·플랫폼별 고유 경기 수, 원문·번역 공개 수, 8개 언어가 완결된 번역 그룹 수, 부분 공개·실패·복구 수를 먼저 표시한다. 수요 신호가 달라 두 리그의 경기 수가 같지 않을 수 있으므로 전체 클릭 합계만으로 우열을 판단하지 않는다. 글당 지표와 같은 기사 그룹의 언어별 차이, 관측 기간과 발행 시차를 함께 본다.

언어 성과는 같은 리그·기사 의도·번역 그룹에서 비교한다. 정상 관측된 공개 페이지의 0클릭은 실제 발행 성과로 포함하되, 번역 누락·발행 실패·분석 미연결은 각각 별도 상태로 남긴다. 페이지는 공개됐지만 색인되지 않은 경우에는 유입 0과 색인 상태를 함께 기록하며 언어 시장에 수요가 없다고 바로 결론 내리지 않는다.

기본 공통 사실과 관전 질문을 언어별로 유지하고, 이해를 돕기 위한 현지화와 제목의 변경은 기록한다. 번역마다 다른 선수·다른 사건으로 기사 주제를 바꾸는 실험은 분리한다. 한 경기 급등이 평균을 좌우하는지와 번역 공개가 경기 시작·종료보다 얼마나 늦었는지도 확인한다.

### 14일 주기와 30일 검토

- 첫 14일에는 후보 발견, 검수, 경기 배정과 발행을 진행하면서 색인·최초 노출·오류를 확인한다. 경기 후에도 도움이 되는 기사와 빠르게 만료되는 정보를 따로 표시하고, 필요한 공개·갱신 작업의 실제 완료 상태를 함께 본다.
- 다음 14일에는 같은 규칙으로 운영하고, 관측 기간을 채운 첫 주기의 글을 검토한다. 오래 쓰이는 설명은 사실을 재확인해 갱신하고, 종료된 이벤트는 종료 상태를 명시한다. 새로워 보이게 하려고 날짜만 바꾸지 않는다.
- 30일 검토는 중간 점검이다. 마지막에 발행한 글은 14일 관측을 채울 때까지 추적한다. 후보 선별 기준이나 발행 규칙을 바꾸면 다음 운영 주기로 구분하고, 변경 전후 표본을 그대로 합쳐 비교하지 않는다.

## 지표

- 주지표: 글당 최초 14개 완결 보고일의 Google 검색 클릭 수. 발행 다음 날부터 14일을 고정해서 관측하며, 그 기간을 채운 글만 비교한다. 색인되지 않아 클릭이 0인 글도 전체 발행 성과에 포함한다.

## 승인 시차와 판정

AdSense 신청일, 승인일, 실제 광고 게재 시작일을 따로 기록한다. 승인 전 수익 0원은 실제 사업 성과에 포함하지만 RPM은 미측정이다. 검색 유입과 광고 심사 상태는 별개로 관측한다.

관측 기간을 채운 같은 언어의 경기 매칭 표본이 부족하거나, 노출이 너무 적어 비교가 한두 번의 클릭에 좌우되거나, 한 경기의 급등이 전체 차이를 만드는 경우에는 판정을 보류한다. 이 실험에는 통계적 우위를 보장하는 최소 표본 수가 정해져 있지 않다. 30일에 반드시 플랫폼 승자를 정하지 않으며, 한두 경기의 성과를 플랫폼 전체의 우위로 확대하지 않는다.

색인·접근·대표 URL 문제가 있으면 이를 먼저 해결하고 기록한다. 정상적으로 노출되는 글에서 반복적으로 확인되는 질문·국가·주제군을 다음 주기의 후보 선택에 사용한다. 사실 오류·중복 질문·추가 가치 부족은 해당 글의 발행을 중단하는 사유이며, 수요 데이터 부족은 수요 검증을 보류하는 사유다.

### 수익 산식

다음 산식의 수익과 비용은 같은 기간·통화로 맞춘다. Page RPM의 페이지 조회 수는 AdSense 보고서와 같은 범위의 분모를 사용하며, 광고가 없는 페이지까지 포함한 다른 도구의 전체 조회 수와 섞지 않는다.

```text
실측 Page RPM = 추정 광고 수익 ÷ AdSense 페이지 조회 수 × 1,000
시나리오 광고 수익 = 시나리오 페이지 조회 수 ÷ 1,000 × 가정 Page RPM
운영 수지 = 광고 수익 − 운영 비용
목표 달성에 필요한 페이지 조회 수 = (목표 운영 수지 + 운영 비용) × 1,000 ÷ 가정 Page RPM
```

가정 Page RPM은 계산을 위한 입력값이며 시장 평균·예상 실적·수익 보장이 아니다. 광고 게재 후 충분한 관측이 쌓이면 실제 국가·기기·유입 구성에 맞는 실측값으로 교체한다. 단기 급등을 유지 가능한 월간 수익으로 간주하지 않는다. 월 환산 수익, 기간 누적 수익, 확정 수익, 실제 입금은 별도로 표시한다.

2026년 10월 17일 기준, 경기 조사부터 공개·갱신까지 이어지는 자동 연결은 완료되지 않았다. 확정한 운영 방향과 아래의 실제 구현 상태를 구분한다.

| 같은 URL 갱신 | GitHub 본문은 재빌드로 바꿀 수 있으나 실제 수정일을 위한 별도 `dateModified`·sitemap `lastmod` 처리가 필요하다. Blogger `posts.patch`는 현재 발행기에 구현되지 않았다. |
| Blogger 발행 | API 발행기 코드는 있으나 OAuth와 정기 실행이 연결되지 않았다. 비공개 저널 보존과 단일 발행 실행자를 준비해야 한다. |
| ChatGPT 예약·Blogger 플러그인 | QuickIris용 예약 자동화는 생성되지 않았다. 확인한 플러그인 검색에서는 사용 가능한 Blogger 플러그인을 찾지 못했으며 연결이 완료된 것으로 간주하지 않는다. |
| 검색·수익 측정 | Search Console·광고 수익 데이터의 자동 수집이 아직 연결되지 않았다. |

스케줄러는 작업을 시작시키는 장치다. 자료 접근, 경기 확인, 원고 생성, 검수, 대기열, 각 사이트의 인증·공개·갱신과 실패 복구가 실제로 연결되어야 경기 변화에 따른 자동 운영을 실행할 수 있다. 재빌드 일정만 변경해 전체 자동 발행이 켜졌다고 표시하지 않는다. 예약 지연·누락에 대비해 공식 변화와 실제 처리 시각·완료 상태를 보존한다.

## 기록 파일

실제 계정·수익·성능 데이터는 공개 저장소에 넣지 않는다. `data/private/`는 Git에서 제외한다. 후보 근거·배정·관측값은 비공개 기록으로 관리하고, 공개 문서에는 실험 설계·지표 산식·코드만 저장한다. 개인 연락처, 사용자 대화, 개인 재정 정보는 포함하지 않는다.
