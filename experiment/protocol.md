# Blogger / GitHub Pages 운영 실험

## 목적

같은 콘텐츠 운영 방식에서 어느 사이트가 검색 방문자와 수익을 더 잘 만드는지 확인한다. 플랫폼당 사이트가 하나이므로 플랫폼 일반의 인과적 우열을 증명하는 A/B 테스트로 해석하지 않는다.

## 배정과 운영

1. 같은 언어·분야·검색 의도·시의성·예상 난이도의 서로 다른 질문을 한 쌍으로 만든다.
2. 쌍 안에서 어느 질문을 어느 플랫폼에 보낼지 발행 전에 무작위로 정하고 배정을 유지한다.
3. 초기 목표는 각 사이트 하루 1편, 30일이다. 데이터·원고 검증을 통과한 글만 발행한다. 특정 글자 수나 게시량이 승인을 보장하지 않는다.
4. 같은 원문을 복제하거나 문장만 바꾼 글을 두 사이트에 발행하지 않는다. 중복 콘텐츠 자체가 자동 제재를 의미하지는 않지만 대표 URL 선택이 비교에 섞일 수 있다.
5. 발행 일정·출처 검증·광고 설정·외부 홍보 조건을 가능한 범위에서 맞춘다. 조건을 바꾸면 날짜와 이유를 남긴다.

## 지표

- 주지표: 게시 후 14일 동안 글당 Google 검색 클릭 수. 14일을 채운 글만 같은 기간으로 비교한다. 색인되지 않아 클릭이 0인 글도 전체 발행 성과에 포함한다.
- 보조 검색 지표: 노출수, CTR, 최초 검색 노출일, 쿼리·국가·기기별 변화. 전체 평균 게재순위만으로 판정하지 않는다.
- 사업 지표: 30일 누적 추정 광고 수익, 확정 수익, 실제 입금, API·도구 비용, 운영 시간. 서로 다른 항목을 혼합하지 않는다.
- 수익 효율: 양쪽 모두 광고를 게재한 공통 기간의 페이지 RPM. 국가·기기·유입 경로 구성이 다르면 이를 함께 본다.
- 운영 품질: 발행 시도/실패 횟수, 검수 글/사실 오류 글 수, 수정에 사용한 시간.

## 승인 시차와 판정

AdSense 신청일, 승인일, 실제 광고 게재 시작일을 따로 기록한다. 승인 전 수익 0원은 실제 사업 성과에 포함하지만 RPM은 미측정이다. 30일에 데이터가 적으면 판정을 보류하고, 한두 글의 성과를 플랫폼 전체의 우위로 확대하지 않는다.

## 기록 파일

실제 계정·수익·성능 데이터는 공개 저장소에 넣지 않는다. `data/private/`는 Git에서 제외한다. 공개 문서에는 실험 설계와 코드만 저장한다.
