# Resume QuickIris work

1. Read `AGENTS.md`, `docs/PROJECT_STATE.md`, `docs/HANDOFF.md`, and current relevant GitHub Issues.
2. Inspect the actual branch head and its latest commits; compare recorded milestones with code, CI and live site behavior. If a user says something was interrupted, treat both success and failure as **unverified** until checked.
3. Select one milestone only. Report: task, scope, prerequisites, already verified results, unresolved actions, and acceptance criteria.
4. Work in batches using stable match/event and article IDs. Before any publish, check existing remote post/URL; an unknown network response is NOT proof that it failed.
5. Validate factual sources, dates, chart values, localization, source licensing, and editorial quality. Avoid unreviewed large-scale mass publication.
6. Commit/test and verify results; update `docs/PROJECT_STATE.md` with UTC date, commit, actual URLs, completed count, failures and next batch. Update the corresponding GitHub Issue.
7. Finish with a concise actual-status report. If blocked, give the concrete blocker and leave an unambiguous next action. Never claim background work.

The long-term product and geographic plan lives in `docs/EXPANSION_ROADMAP.md`. Do not expand beyond NBA/EPL without a new decision.
